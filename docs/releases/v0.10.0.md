## Bekannte GE-Zuordnungen erklären

Der Proton-Manager zeigt die Anzahl installierter Tools mit bekannter
expliziter Spielzuordnung und die Summe ihrer gemessenen Größen. Ein Tool wird
auch bei mehreren Spielzuordnungen nur einmal gezählt. Fehlende Größen bleiben
nicht gemessen oder teilweise gemessen; belegte Null erscheint als `0 B`.

Ein erreichbarer Erklärknopf ersetzt die bisherigen Zuordnungs-Tooltips.
Globaler Standard, externe Werkzeuge und andere Workflows bleiben mögliche
Nutzer eines Tools ohne bekannte Zuordnung. Die Erklärung zum Löschumfang
stellt klar: Das Entfernen einer GE-Version entfernt das Tool-Verzeichnis,
nicht die compatdata-Prefixes seiner Spiele. Keine Löschentscheidung oder
zusätzliche Zuordnungslogik.

## Prefix-Ordner öffnen

Im Spiel-Drawer öffnet ein Klick den frisch geprüften Standard-Prefix im
Dateimanager. Unklare Startoptionen, jedes Vorkommen von
`STEAM_COMPAT_DATA_PATH` und ein laufender Scan sperren die Aktion mit
sichtbarem Grund. Dieselbe Erkennung speist jetzt auch den externen
Compatdata-Hinweis; er schlägt damit auch bei Zuweisungen mitten in den
Startoptionen an. Die Aktion misst nichts, erstellt
keinen Prefix und verändert keine Steam-Datei über Protium.

Der enge native Command akzeptiert Library und AppID, prüft Snapshot und
Manifest sowie jede Prefix-Komponente und übergibt den vom Kernel ermittelten
Ordnernamen an den Systemhandler. Kein generisches Pfad-Öffnen und keine neue
Capability. Fehler erscheinen als feste deutsche oder englische Meldungen;
rohe Backendfehler und Zielpfade werden nicht angezeigt. Antworten nach
Spielwechsel, Rescan, Speicherversuch oder Schließen werden dauerhaft verworfen,
auch nach Rückkehr zum gleichen Kontext. Ein FIFO-Manifest wird ohne blockierendes
Warten als unlesbar abgewiesen; weitere Snapshotzugriffe bleiben möglich.

„Dateimanager gestartet“ bestätigt nur den Handlerstart. Der Handler löst den
Pfad selbst erneut auf; ein gleichzeitiger Pfadtausch bleibt eine dokumentierte
Grenze. Er kann mit bestehenden Nutzerrechten selbst Daten verändern und läuft
nach dem Ende von Protium gegebenenfalls weiter. Details:
[Prefix-Öffnen und Sicherheitsgrenzen](../../SECURITY.md#prefix-ordner-im-dateimanager-öffnen).

## Prüfnachweise

Automatisierte de/en-Tests für Zustände, Fehlertexte und alte Antworten sowie
Rust-Fixtures für Autorität, Symlinks, fehlende/unlesbare Ordner und Pfadtausch.
Ein Grenztest belegt, dass der Handlerpfad die Library selbst nie öffnet.

Pflichtgates grün: `npm run check` (131 Dateien), 963 Tests in 60 Dateien,
`npm run vite:build`, `cargo fmt --check`, `cargo build`, 274 Cargo-Tests und
`cargo clippy --all-targets -- -D warnings` (2026-09-09). Zwölf neue
Regressionen sichern FIFO/Lock und die Anfragelebensdauer ab.
Historische Mutationsevidenz vom 2026-09-07, beim Review-Fix nicht erneut
ausgeführt: Stryker über `src/core`: 76,11 %
bei Schwelle 69 %; alle Mutanten des neuen Sperrgatters und des Adapteraufrufs
sterben. Acht gezielte Mutationen der nativen Guards (Library-Eingrenzung,
Identitätsprüfung, Manifestpflicht, `(deleted)`-, NUL- und Absolutpfadprüfung,
`gio`-Fallback, AppID-Mismatch) scheitern in einer isolierten Kopie jeweils an
benannten Tests; zwei Tests wurden dafür geschärft, weil nachgelagerte Guards
sie zuvor grün hielten. `cargo audit` lief nur lokal ohne Datenbankupdate;
`npm audit` bleibt ohne Freigabe zur Metadatenübertragung offen.

Realer Teil-Smoke am 2026-09-09 per Nutzer-Screenshot bestanden: Dolphin
zeigt den Prefix-Ordner, Protium meldet „Dateimanager gestartet“. Ausführung
laut Nutzer über `npm run tauri dev`; AppImage noch ungeprüft. Weitere reale Störfälle bleiben
ungeprüft; schnelle Kontextwechsel sind automatisiert abgesichert.
